# Contributing

Thanks for your interest in improving `relaybox`.

## Before Opening a PR

- open an issue for substantial API or behavior changes
- keep changes narrowly scoped
- include or update tests when behavior changes
- update docs when public APIs move

## Development

```bash
go test ./...
```

## Style

- prefer small, explicit APIs
- avoid framework-specific assumptions in the core package
- keep reliability guarantees clearly documented
